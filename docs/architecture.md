# 架构与交付边界

```mermaid
flowchart LR
  I[获准录音与素材] --> R[Record 和原件引用]
  R --> M[带来源的检索结果]
  M --> A[Agent 行动草稿]
  A --> C[用户确认]
  C --> E[设备或服务适配器]
  E --> T[实际回执和任务状态]
```

SwiftUI 提供原生 iOS 入口。React / TypeScript 提供官网与交互原型。数据、授权、审批与回执由 FloWork 管理，模型与设备通过适配器接入。

当前基础与设计目标分别描述：原生 App 已有记录、检索和确认流程基础及内部 TestFlight 交付记录；网页 `/flow-space` 和首页点击示例仅为合成数据原型。ESP32 模糊检索、家庭照片打印、录音标记后主动通知及便携打印需按现场实机路径验收。无公开生产 API 可供此网页调用。

选择原生 iOS 是为了录音、蓝牙、通知和系统授权的能力。选择网页展示是为了评委跨设备查看。迁移到其他原生平台仍需适配其采集与执行接口，不能只替换 UI。

设备在线、检索命中、用户确认、任务受理与执行完成是不同状态。未找到依据时补问；接口不可用时显示失败或等待；重要动作不能由模型自行跳过确认。跨端任务需避免重复执行。
