# SDK 使用与设备适配方法

本说明介绍如何把授权录音设备接到 FloWork 的产品流程，不分发厂商 SDK，不公开私有服务接口。下述名称是职责说明，不是声称厂商存在同名 API。

## 获取与初始化

1. 向 Anker / soundcore 官方申请相应 SDK、设备权限和版本文档。二进制、账号和密钥不随本仓库分发。
2. 依官方支持矩阵选择平台、系统版本和设备型号，在原生宿主中集成 SDK。
3. 从受保护的配置渠道加载所需配置。浏览器、公开仓库、README、日志和截图不放置密钥。
4. 由用户授予 SDK 所需的蓝牙、麦克风或文件访问权限，明确展示已连接设备和账号。

## 录音和标记接入

1. 订阅官方 SDK 支持的设备状态、录音同步与标记事件。具体回调、时间单位和离线行为依所用版本核对。
2. 保留源录音 ID、源时间戳、标记位置、素材版本和同步状态。尚未同步的音频显示等待，不凭标记凭空生成原文。
3. 将原件交给应用存储模块，Record 只维护素材引用和时间关系。派生转写保留定位信息。
4. 用标记前后真实转写生成待办候选，把来源片段、目标和参数一起交给用户核对。
5. 确认后才让执行器调用获准目标，记录成功、失败或结果待核实。设备受理不等于已经打印出纸。

## ESP32、Flo Home 与打印设备

ESP32 适合语音输入和终端反馈。检索与模型调用放在获准的应用或网关服务，终端不持有全库或管理员凭据。Flo Home 按目标打印机的正式接口、网络条件和授权方式做适配。每个适配器独立验证连接、任务提交、状态读取和重复请求处理。

照片场景先把自然语言转换为检索线索，查询有权限的记录，再读取相应照片原件。多个候选由用户核对。家庭 NAS 和云存储是可替换部署选择，不意味着任意 NAS 型号已经兼容。

## 迁移到其他设备或 Agent

跨平台复用 Record 引用、来源定位、行动草稿、确认与回执的语义。各平台重新实现录音、文件访问、通知、打印和安全存储适配。外部 Agent 只拿到用户许可的资料与能力，模型本身不获得凭证或自动执行权限。

目前公开仓库提供网页原型和本方法说明。没有可供第三方直接调用的公开生产 SDK；不要将此方法说明当成服务可用性承诺。
